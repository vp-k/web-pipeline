# 중단 전에 확인할 것

단계 전환이나 진단 명령의 nonzero만으로 턴을 끝내지 않는다. 실제 상태와 실패 원인을 읽고 이미 요청된 범위에서 가능한 다음 조치를 수행한다.

| 상황 | 계속할 조치 | 실제 사용자 결정이 필요한 경우 |
| --- | --- | --- |
| 승인 기록 누락 | 실제 대화의 같은 단계·범위 동의를 전사하고 재검사 | 새 보호 결정, 바뀐 바인딩, 철회, 원문 부재/모호함 |
| 시간 경고 | warn이면 계속하고 사용량 보고 | enforce의 추가 예산이 승인되지 않음 |
| 검증 실패·리뷰 수정 요청 | 로그 조사 → 수리 → 필요한 재검증·리뷰 | 범위 변경, 위험 수락, 테스트 예외 |
| WAITING·BLOCKED | 의존성·기록·환경 복구 후 정상 전이/retry | 권한·자격 증명·미정 요구사항 등 실제 외부 입력 |
| BUSY·남은 리스 | 살아 있는 작업은 기다리고, 종료가 확인된 리스만 recover | 다른 작업자의 상태를 확인할 수 없음 |
| Git 오류·충돌 | 변경을 보존하며 같은 요청 안의 통합을 마무리 | 변경 폐기나 제품 동작 선택이 필요함 |
| 세션 재개·다음 작업 | STATE·큐·증거를 읽고 유효한 부분부터 이어감 | 새 요청 범위나 미해결 결정 |
| 요구사항 질문 | 기존 자료·답을 재사용, 독립적으로 가능한 작업 진행 | 구현 결과를 바꾸는 미해결 질문 |
| 리뷰 도구 부재 | 실제 별도 로컬 검토 후 자체 리뷰로 기록 | 정책상 사람/독립 리뷰가 필수이며 확보되지 않음 |
| 보관 | 명시적 범위의 일괄 보관 요청은 매번 묻지 않고 재사용 | 범위가 모호하거나 보관 실패가 실제 후속 작업을 막음 |
| Release·배포 | 일반 개발 완료 기준에 넣지 않음 | 해당 실행이 요청되었고 필요한 결정이 남음 |

선택적 보관을 필수 승인 질문에 끼워 넣지 않는다. 보관 요청이 없다면 완료 보고를 보관 여부에 묶지 않는다. 유효하지 않은 DONE/Phase 증거나 미완료 큐를 우회하지 않는다.

강제 실패·동일 실패·외부 재시도·스텝 제한은 유지한다. 무한 재시도, 카운터 초기화, 테스트 약화, 미래 증거의 사전 승인은 허용하지 않는다. 이미 받은 구체적인 복구·갱신 요청은 재확인하지 않고 해당 범위에서 실행한다.
