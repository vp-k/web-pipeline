# Internal implementation contract (v2.1)

## Review remediation amendments

These amendments supersede narrower v2 interface descriptions below; the persisted schema version remains `2.0`.

- `policy_check(..., gate="progress")` and `validate --gate progress|merge` distinguish an in-progress diagnostic from merge authorization. Merge checks all active tasks, requires DONE and current evidence/signatures, and forbids kit mode or task selection. Policy runs invoke the same validator.
- `acceptance_checks(root, state)` supplies task-specific checks to `required_checks(..., task_checks=())` for Full/Release. Prepare rejects disabled or Full-ineligible acceptance commands.
- Baseline runs are DRAFT-only. Returning to DRAFT requires `revise`; duplicate run IDs are rejected before mutable attempt/evidence state changes. Authorized NOT_APPLICABLE checks do not count as failures.
- `output_exclusions` rejects overlaps with governed inputs; tracked files cannot be hidden in report, generated, or implicit cache exclusions (except `.gitkeep`). `source_files` is the common enumeration used by snapshot and archive capture.
- `archive` captures `SOURCE.zip` and `SOURCE_MANIFEST.json`; `verify_source_bundle` validates exact bytes against the approved Full tree digest. Known local credential filenames fail capture without writing a bundle. Historical evidence is not a current merge gate.
- CI context resolves the comparison base to a commit and requires an explicit numeric evidence workflow run for adopted projects. Project-to-kit downgrades cannot bypass the merge gate. Actual protected CI and trusted human key custody remain external requirements.

Package `web_pipeline/`, Python 3.11+. Use stdlib unittest tests under `tests/`; tests own isolated tempfile repositories. No agent edits another agent's files. Apply patches for files. No live production commands, real approvals or Git initialization in the user's source directory.

## Common interface (primary owns common.py)

`PipelineError(Exception)`, `utc_now()->str`, `parse_time(str)->datetime`, `canonical_hash(obj)->str` (64 hex), `hash_file(Path)->str`, `safe_path(root, relative, must_exist=False)->Path` (reject absolute, traversal and symlinks), `atomic_json(path,data)`, `atomic_text(path,text)`, `lock(root,name)` context manager, `load_config(root, kit=False)->dict`, `validate_schema(root,name,data)`, `read_state(root,task_id)->dict`, `write_state(root,state)` (STATE.md JSON fenced block), `source_fingerprint(root,config,state)->str` (64 hex), `code_snapshot(root,config)->dict` (`commit`, `tree_digest`, `dirty`), `artifact_manifest(root)->list` (path,size,sha256).

Schemas are packaged in `Schemas/`. load_config validates version 2 schema, IDs, coverage/profile consistency, protected rule coverage, paths and project readiness unless kit=True. Code snapshots exclude `.git`, configured report root, `Docs/Work`, `.venv`, `__pycache__`, `.pytest_cache`, node_modules, and configured generated paths. `generated_paths` are only for untracked build/test output; a tracked file under one is rejected so source cannot be hidden. Fingerprint includes config and configured source file hashes plus task revision and BRIEF.md, DOR.md, PLAN.md/EXEC_PLAN.md, ACCEPTANCE.json, referenced ADR records. No STATE mutable statuses in fingerprint. `prepare_task` stores `fingerprint` after documents are populated.

## Config v2 shape

`schema_version: "2.0"`, `project: {name, mode:"kit"|"project", ready:bool, report_root:"Reports/Pipeline", supported_domains:[...]}`, `sources: {product_spec:path,feature_spec:path,api_contract:path,data_contract:path,security_policy:path,architecture:path}` (all six required), `risk: {domain_floor:{...},domain_protected_map:{domain:[protected...]},protected_rules:{id:{tier,domains:[...],roles:[...],checks:{profile:[id...]}}},path_rules:[{pattern,domains,protected_changes,tier}]}`, `verification:{requirements:{domain:{Baseline:[],Fast:[],Full:[],Release:[]}},policy_checks:[id...],commands:[{id,enabled,profiles:[],argv:[],cwd:".",timeout_seconds:300,artifacts:[],environment:"local"|"test"|"staging"|"production"}]}`, `iteration_limits:{total_attempts:5,same_failure:3,external_retries:2,elapsed_minutes:120}`, `evidence:{desktop:{width:1440,height:900},mobile:{width:390,height:844}}`.

Release inherits Full requirements. Protected requirements apply regardless of declared domains. Missing command/disabled yields NOT_RUN, never PASS. Production commands are forbidden by this local engine; Release is readiness verification, not a deploy executor. Checks use argv; reject shell compound execution (powershell -Command, sh -c, cmd /c etc) and require dedicated scripts for compound workflows. Full/Release browser screenshots use `screenshots/manifest.json`: [{path (run-relative),kind:"desktop"|"mobile",url,width,height}]. Validate decoded image dimensions against config and manifest. Report contains image/file hashes. Required artifacts are run-relative glob patterns, absence fails check.

## State/governance interface (agent 1)

`create_task(root,task_id,title,tier,domains,protected_changes=None,migration_class="none",base_ref=None)->dict`, `prepare_task(root,task_id,implementer)->dict`, `classify(root,config,state)->dict`, `policy_check(root,task_id=None,kit=False,trust_path=None,base_ref=None)->dict` returns {status,errors,warnings}; with no task_id scan ALL tasks. `transition(root,task_id,status,trust_path=None)->dict`, `revise_task(root,task_id,reason)->dict` invalidates evidence/approvals and increments revision but does not reset cumulative iteration budgets; `validate_approvals(root,config,state,roles,phase,trust_path=None,snapshot=None,run_id=None)` raises on invalid. There is no signed or unsigned iteration-reset API.

Task shape: `schema_version`, `task_id`, `title`, `status` (DRAFT READY IN_PROGRESS VERIFYING REVIEW DONE BLOCKED), `revision` integer, `requested_tier`, `risk_tier`, `change_domains`, `protected_changes`, `migration_class`, `base_ref`, `implementer`, `fingerprint`, `approvals` (paths to signed JSON records), `decision_records` (paths), `exceptions` (paths), `baseline_run`, `full_run`, `release_run` (nullable IDs), `iteration:{attempts,same_failure,external_retries,started_utc,last_failure}`, `release_status` (NOT_READY READY VERIFIED), `blockers:[]`, `created_utc`, `updated_utc`. No writable PASS status parameters. ACCEPTANCE.json: {criteria:[{id,description,checks:[id...]}]}, required populated for READY/DONE.

Trust path must be external to project (explicit CLI --trust or WEB_PIPELINE_TRUST). JSON {identities:{name:{type:"human",roles:[],public_key:base64 raw Ed25519}}}. Signed record {payload:{task_id,revision,fingerprint,phase:"design"|"review"|"release"|"exception",role,identity,approved_utc,expires_utc,outcome:"APPROVED",scope:[protected...],tree_digest (review/release),run_id (review/release),run_digest (review/release SHA256 of summary.json bytes),conditions:[{description,status:"PASS",evidence:path,sha256}],...},signature:base64}. Every condition must be PASS with current hashed evidence; there is no APPROVED_WITH_CONDITIONS outcome. Signature is over json.dumps(payload,sort_keys=True,separators=(',',':'),ensure_ascii=False). Root primary builds schema with these fields, optional check_id/reason for exception. ADR record {id,title,status:"PROPOSED"|"ACCEPTED",task_id,revision,scope:[protected...],context,decision,risks,recovery}; human approval is a separate signed design record. Never accept a role just because it isn't Reviewer.

## Runner interface (agent 2)

The summary also requires `policy_snapshot`, a SHA256 of verification-relevant configuration. `validate_run` accepts `trust_path=None` to revalidate signed exceptions.

`run_profile(root,task_id,profile,trust_path=None,run_id=None)->dict` returns summary and writes evidence. `validate_run(root,config,state,run_id,profile=None,require_current=True)->dict` verifies schema, task/fingerprint/source snapshot/manifest hashes/required checks. A genuinely executed failing Baseline may be retained as `baseline_run` to describe original code when Policy passed and required logs/hashes remain valid; its summary stays FAIL and CLI stays nonzero. NOT_RUN/BLOCKED is not a baseline. Baseline may use the old code snapshot but must have the current task fingerprint at READY. Full pointers require a passing run or valid signed exceptions. Review signatures bind tree digest, Full run ID, and the SHA256 of that run's summary. Release readiness requires a current prerequisite Full run; signed release records bind that Full run (not a deployment) with tree digest and Full summary digest. Runner can import governance functions lazily to avoid circular imports. Iteration applies Fast/Full retry loop, record each execution atomically under task lock; no lock recursion. Other agents shouldn't independently lock within caller-held locks.

Summary shape: schema_version,run_id,task_id,profile,status,fingerprint,snapshot,started_utc,completed_utc,checks:[{id,status,exit_code,duration_ms,log,reason}],artifacts:[{path,size,sha256}],failure_fingerprint (nullable). SHA256 integrity + trusted CI/environment is explicit trust boundary: a local agent with write access to engine and evidence cannot be cryptographically policed by those same files. Signed human approvals bind resulting evidence and source where applicable.

## Integration interface (agent 3)

`archive --task --trust` revalidates current DONE evidence and signatures, then moves the single task directory to `Docs/Archive/<TaskId>-r<revision>` without overwrite. Archived tasks are historical evidence, excluded from active policy scans and code snapshots/classification. Run evidence is retained; no archive action creates a human approval.

`python -m web_pipeline [--root ROOT] {validate,new,prepare,attach,transition,revise,run,fingerprint,init}`. validate supports --kit,--task,--base-ref,--trust. new flags --task,--title,--tier,--domains comma list,--protected comma list,--migration,--base-ref. prepare --task --implementer seals populated documents and fingerprint. attach --task --kind adr|approval|exception --path validates schema/task/revision and adds a record reference; it does not establish approval. ADR attachment is limited to an unprepared DRAFT. transition --task --status --trust; revise --task --reason; run --task --profile --run-id --trust; fingerprint --task. init --target writes package/docs/config without overwrite after preflight (no external accounts).

Primary owns __init__.py, common.py, requirements.txt, Schemas, pipeline.config.yaml. Agent 1 owns governance modules/tests; agent 2 owns runner/evidence modules/tests; agent 3 owns __main__.py, cli.py, Scripts adapters, README/docs/templates/example/CI/tests.
